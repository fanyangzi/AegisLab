# AegisLab 设备 taxonomy 调研与落地建议

更新时间：2026-10-09

这份调研用于把 AegisLab 的实验室空间、资源图谱和 AI 审查对象从当前的六种抽象物件，扩展为高校分析测试中心、化学学院共享平台和研究院公共技术中心中真实存在的设备体系。设备名称来自公开的高校/研究院设备平台；风险与控制点按公开安全管理办法和设备使用规则归纳，不能替代具体设备的厂家说明书、SDS 或校内制度。

## 2. 建议的领域模型

当前 `Kind = hood | bench | storage | analyzer | sink | waste` 只适合做最粗的 3D 颜色分组。建议保留 `kind` 作为场景渲染族，同时新增以下字段，不破坏既有数据：

```ts
type EquipmentFamily =
  | 'containment'       // 通风与生物/洁净隔离
  | 'workstation'       // 操作台、称量、合成、装配
  | 'separation'        // 色谱、萃取、纯化、离心
  | 'spectroscopy'      // NMR/EPR/IR/UV/Raman/荧光
  | 'mass_analysis'     // GC-MS/LC-MS/MALDI/ICP-MS
  | 'structure_material' // XRD/XPS/SEM/TEM/AFM/BET
  | 'thermal_process'   // 烘箱、马弗炉、热分析、反应器
  | 'cold_chain'        // 冰箱、低温、液氮
  | 'gas_vacuum'        // 气瓶、气路、真空、尾气
  | 'bio_molecular'     // PCR、酶标、流式、凝胶、培养
  | 'safety_response'   // 洗眼、喷淋、报警、消防、门禁
  | 'waste_environment' // 废液、固废、环境监测
  | 'utility';          // 纯水、电源、空压、HVAC

interface EquipmentOperationalProfile {
  family: EquipmentFamily;
  subtype: string;
  aliases: string[];
  typicalUse: string;
  hazardTags: string[];
  controlTags: string[];
  utilityRequirements: string[];
  requiredTraining: string[];
  calibrationOrInspection: string[];
  evidenceKinds: ('sop'|'inspection'|'sds'|'training'|'calibration'|'reservation')[];
  sourceRefs: string[];
}
```

`hazardTags` 只表示审查索引，不直接生成事故结论；真实放行仍应以 SOP、SDS、设备 SOP、检查记录和人工审核为依据。

## 3. 可落地的设备 taxonomy

下面的叶子类型适合直接作为 `subtype`，每种设备都应能关联到房间、实验计划、化学品、SOP、证据、维护/校准和预约。

### A. 通风、隔离与洁净

| subtype | 典型用途 | 主要风险/控制点 |
|---|---|---|
| 普通化学通风柜 | 挥发性/有毒/腐蚀性试剂操作 | 面风速、视窗高度、排风联锁、柜内负载、尾气处理 |
| 高氯酸通风柜 | 高氯酸及强氧化性体系 | 专用管路、清洗记录、禁用有机残留 |
| 放射性/同位素通风柜 | 放射性示踪实验 | 许可、污染监测、专用废物链 |
| 无管式过滤通风柜 | 小量、特定吸附过滤场景 | 滤芯寿命、适用化学品清单，不能替代普通排风 |
| 生物安全柜 II 级 | 细胞/微生物相关操作 | 生物气溶胶、HEPA、年检与消毒 |
| 洁净工作台 | 非危险样品的洁净操作 | 不可用于有毒挥发物；压差、HEPA、紫外灯管理 |
| 手套箱/惰性气氛箱 | 无水无氧合成、敏感材料 | O2/H2O 指标、再生记录、气密性、溶剂兼容性 |
| 局部排风臂/捕集罩 | 局部源头捕集 | 风量、覆盖范围、软管完整性 |
| 洁净室/负压操作间 | 高洁净或高危隔离 | 压差、门禁、换气、进入培训 |

## 4. 设备与 AI 场景的连接方式

仅新增设备名称不会体现 AI。每个设备节点应能参与至少四个可见的 AI 动作：

1. **计划解析**：从 SOP/实验计划抽取设备、型号能力、温度/压力/气体/排风要求，自动建立步骤—设备边。
2. **前置审查**：将设备 profile 与化学品危险性、步骤参数和房间控制点比对，输出“缺什么证据、为什么阻断、依据哪一行原文”。
3. **运行态推理**：结合预约、校准到期、维护窗口、传感器/门禁状态，判断“可用但不可放行”的具体原因。
4. **方案推演**：为同一个实验生成多个资源方案（例如 GC-MS 与 LC-MS 的替代路径），展示安全控制覆盖、时间和证据差异，由人工选择。

建议在设备详情中同时显示：

- `AI 摘要`：模型识别出的用途、危险源和控制动作；
- `规则证据`：确定性规则、SOP 行号、SDS/检查记录链接；
- `待补项`：缺少校准、培训、尾气处理、预约或相容性证据时的具体补救动作；
- `人工状态`：待复核/已确认/驳回，禁止把模型输出直接写成“已批准”。

## 5. 建议的首批真实感种子数据

不要把所有设备都塞进一个房间。建议建立三个相互关联的空间：

1. **合成与前处理区**：6 通风柜、4 操作台、分析天平/称量台、旋蒸、氮吹、微波合成、反应釜、离心机、超声清洗、废液柜、酸碱柜、防爆柜、洗眼器/喷淋、气瓶柜。
2. **共享分析平台**：GC、HPLC、UPLC、LC-MS/MS、GC-MS、ICP-MS、ICP-OES、NMR、EPR、FTIR、UV-Vis-NIR、荧光、拉曼、XRD、XPS、BET、元素分析、TOC，以及独立的仪器室/培训/预约关系。
3. **低温与交叉研究区**：-80℃冰箱、液氮罐、冷阱、手套箱、洁净工作台、PCR/qPCR、酶标仪、凝胶成像、共聚焦、流式、气体报警、环境监测和门禁。

建议首批不低于 60 台设备、12 个设备房间/区域、20 个以上化学品/控制关系、15 个 SOP/检查/校准证据。数量本身不是卖点，关键是每台设备都有用途、风险、控制和证据链，能够被 AI 审查到。

## 6. 引用和使用边界

- 页面上的品牌型号、数量、价格和参数属于各校/研究院在页面发布时的具体实例，不能直接当作 AegisLab 的机构事实；项目内可作为“示例资产来源”展示。
